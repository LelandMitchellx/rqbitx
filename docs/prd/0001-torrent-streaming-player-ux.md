# 0001. 种子流媒体播放交互与状态流转规格说明书 (PRD)

- **状态**: 已实现 (implemented)
- **版本**: v1.0.0
- **日期**: 2026-10-15
- **关联架构**: [ADR-0002 便当盒无边框纯平设计](../adr/0002-bento-grid-borderless-ui-design-system.md), [ADR-0004 MediaKit 流式播放集成](../adr/0004-media-kit-torrent-video-streaming.md)

---

## 1. 业务背景与目标

为用户提供极简、顺畅的“添加磁力 -> 自动解析元数据 -> 浏览文件 -> 边下边播”离线下载与多媒体流播放体验。
解决传统 BT 客户端常驻庞大播放窗口、元数据等待期无反馈、必须等待整包下载完成才能预览等痛点。

---

## 2. 核心用户故事与场景

1. **零配置开箱即用**：
   - 用户打开 App，系统在后台静默自动拉起底层 `rqbit` 原生引擎并绑定端口，无需用户手动寻找“启动服务”开关。
2. **沉浸紧凑的首屏**：
   - 在用户尚未添加任何种子任务前，主屏界面保持纯净紧凑的便当盒（Bento Box）卡片流，**不展示冗余且占空间的空播放器窗口**。
3. **任务添加与异步元数据感知**：
   - 用户粘贴磁力链接后，App 立即发起添加任务请求。
   - 若种子元数据尚未就绪，展示柔和的加载状态与文案，后台自动轮询直至解析出完整文件列表。
4. **按需媒体播放**：
   - 文件列表中清晰展示每个文件的名称与格式化大小。
   - 自动识别视频/音频文件并展示醒目的「播放」操作按钮。
   - 点击「播放」从屏幕底部滑出播放面板（Modal Bottom Sheet）启动实时切片流，关闭弹窗时自动停止播放，释放资源。

## 3. 详细交互规格与状态机

### 3.1 引擎生命周期（自动、手动与热重启韧性）
- **热重启（Hot Restart）无缝重连**：
  - Flutter 触发热重启时，底层 Rust 守护引擎与活跃下载任务保持常驻运行，不随 UI `dispose()` 销毁。
  - 重新挂载时通过 `RqbitServer.current()` 瞬间接管已有端口，并通过 `GET /torrents` 自动还原正在进行的任务和文件列表。
- **初始化时自动拉起与默认存储路径解析**：
  - `initState` 阶段通过 `addPostFrameCallback` 触发 `RqbitServer.start()`。
  - **默认存储路径策略**：优先使用 `path_provider` 的 `getDownloadsDirectory()`（在平台 Download 目录下创建 `rqbitx_downloads`），若平台不支持或返回空则自动以 `getTemporaryDirectory()` 兜底，确保跨平台鲁棒性。
  - 启动后建立独立的强类型 `RqbitClient(baseUrl: server.url.toString())` 进行全部业务交互。
  - 服务状态自 `Starting...` 流转至 `Online`，UI 顶部状态徽章同步呈现绿色高亮 `LIVE`。
- **手动启停与兜底**：
  - 用户可随时在「Service Lifecycle」卡片中手动切换启停。
  - 停止服务时，自动中断正在轮询的元数据定时器，并清空当前任务与文件视图。

### 3.2 任务添加与元数据解析流转
```text
[ 用户输入 Magnet ] 
        ↓ 点击「添加种子任务」
[ POST /torrents?overwrite=true ]
        ↓
[ 提取 info_hash / id ]
        ├── files 存在且非空 ────→ [ 立即渲染文件列表 ]
        └── files 为空 (元数据拉取中) ─→ [ 启动 2s 轮询 GET /torrents/{id} ]
                                            ↓
                                   [ 元数据就绪，刷新文件列表 ]
```

- **轮询策略**：
  - 每 2 秒请求一次 `GET /torrents/{id}`，单次最长轮询 60 秒（30 次）。
  - 提供手动「刷新文件列表」图标按钮，允许用户随时发起即时刷新。

### 3.3 文件列表与媒体过滤
- **展示字段**：文件图标、文件名（单行截断省略）、友好容量（B / KB / MB / GB）。
- **媒体文件匹配规则**：
  - 文件后缀大小写不敏感匹配：`.mp4`, `.mkv`, `.webm`, `.avi`, `.mov`, `.ts`, `.flv`, `.mp3`, `.flac`, `.wav`, `.m4a`, `.aac`。
- **操作响应**：
  - 媒体文件：显示蓝色高亮「播放」按键。
  - 普通文件：仅显示中性灰色「文件」属性标签。

### 3.4 底部抽屉播放器（Modal Bottom Sheet）
- **触发机制**：点击任一媒体文件右侧的「播放」按钮。
- **直连地址组装**：`http://127.0.0.1:<port>/torrents/<id_or_infohash>/stream/<file_idx>`。
- **播放器面板组件构成**：
  1. **顶部拖拽指示条**：支持用户手势快速向下滑动关闭。
  2. **媒体元信息栏**：文件全称、rqbit 实时流切片说明，以及独立关闭按键。
  3. **16:9 播放视窗**：黑色背景圆角视窗，搭载 `Video(controller: _videoController)`。
  4. **地址与拷贝栏**：显示当前流式传输的内网 URL，并提供一键复制至剪贴板功能。
- **生命周期清理**：
  - 当 Bottom Sheet 关闭（滑落或点击空白/关闭按钮）时，触发 `whenComplete` 回调，立即执行 `_player.stop()`，彻底杜绝后台静默占用 CPU/网络或产生意外声音。

### 3.5 任务删除与本地物理文件同步清理
- **交互入口**：
  1. **卡片右上角快捷操作**：任务标题栏右侧配有红色垃圾桶危险图标按钮（带防抖 loading 状态）。
  2. **卡片底部全宽按钮**：任务文件列表下方配有红色醒目线框按钮「删除任务并清理本地文件」。
- **防误触确认机制**：
  - 点击后弹出居中危险确认对话框（`AlertDialog`），明确告知用户：“此操作不仅会从后台移除任务，还会同步彻底删除本地磁盘已下载的全部切片与媒体文件，不可恢复。”
- **后台请求与清理流程**：
  - 立即终止正在进行的元数据轮询定时器（`_metadataPollTimer?.cancel()`）。
  - 若正在流式播放视频，立即停止播放器（`_player.stop()`）。
  - 发起 `POST /torrents/{id_or_infohash}/delete` HTTP 请求。librqbit 引擎在从内存 session 卸载任务的同时，同步递归删除该种子在本地 `downloadDir` 磁盘目录下生成的全部切片数据与文件夹。
  - 成功后清空当前前台种子 ID、名称、文件列表与流地址状态，弹出绿色 SnackBar 提示用户清理完毕。

## 4. UI 视觉设计要求 (Pure Flat Bento Box)

- **纯平无阴影**：遵照 ADR-0002 规范，所有 Bento 卡片与 Bottom Sheet 容器均移除任何 `boxShadow`，依靠 `#FFFFFF` 背景与 `#F1F3F7` 浅灰底色的对比表达层次。
- **大圆角与内边距**：卡片统一使用 22px 柔和圆角，容器内边距统一为 18~20px。
- **按键触感**：主操作（启动、添加、播放）使用现代扁平色块（绿色、蓝色、红色），无悬浮投影。
